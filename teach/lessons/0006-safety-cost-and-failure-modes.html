Privacy — what leaves, where it is disclosed

The editor shows, and the spec requires (D10, §4.10):

“Text mapped into Input is sent to the selected AI service and, for aggregators such as Puter, may be processed by an underlying model provider. Do not map secrets or regulated data without approval. Usage may be billed to the configured account.”

What that means technically:

  • Only the resolved input (plus system prompt, schema, temperature, token cap, model ID) is sent to the provider. No trigger payload beyond what you templated; no instructions beyond the system line; no credentials in the request body beyond the bearer token/API key.
  • Outputs are persisted to ZapRun.metadata in Postgres — they contain personal data if input did. Existing retention/access applies; privacy review is an explicit owner gate (spec §6 table).
  • Logs never contain prompts/bodies/keys — provider errors are sanitized via safeAiError to a redacted message. Tests confirm redaction (packages/ai/tests/execution.test.cjs).
Two explicit warnings to obey
  1. Do not map secrets/regulated data without sign-off on retention/zero-retention policies per provider/aggregator/custom endpoint.
  2. Never wire AI output directly into money transfers — schema checks do not establish financial correctness (sendSolana.ts still requires SOLANA_PRIVATE_KEY and throws otherwise). Add deterministic bounds, validation, and human approval.

SSRF & credentials — why BYOK is not “any URL”

A user-supplied baseUrl is an SSRF surface even with BYOK. Applicable to openai_compatible create/update/probe/runtime — spec §4.12 checklist, implemented in packages/ai-connections/src/transport.ts:

  • HTTPS + cert validation; port 443-only start; reject creds/fragment/query/IP literal/malformed URLs.
  • Canonicalize hostname/path; exact operator-approved hostname match (no endswith(attacker.com.example.com) suffix trick).
  • Resolve A/AAAA — block loopback, private, link-local, reserved, multicast, unspecified, IPv4-mapped IPv6 bypasses, metadata endpoints.
  • Bind validated destination to actual connection (TLS hostname verification) or use egress proxy — DNS preflight alone is not enough vs rebinding.
  • Disable redirects; never forward Authorization. Bounded time/bytes/concurrency.

Credentials: platform keys are env-only; BYOK keys encrypted via packages/ai-connections/src/crypto.ts — AES-256-GCM, fresh random nonce per encryption, AAD = id+ownerId+provider. Keyring in AI_CONNECTION_ENCRYPTION_KEYS / _ACTIVE_KEY_ID, rotation/re-encryption runbook required before production BYOK (operations guide). Revoking a connection (DELETE → soft-revoke) prevents future runs; in-flight request cannot be recalled — next-run fails clearly, never silently switches to platform key.

Rollback & revocation — “disable AI” is not “delete ciphertext”

// Spec phase table says:

Disable:   Flip AI_PUTER_ENABLED false + clear AI_COMPATIBLE_ALLOWED_HOSTS (host list empty = deny-all)
           → new runs fail fast at save/validation; in-flight work must drain first
Revoke:    DELETE /api/ai/connections/:id → soft-revoke (affectedZapCount returned)
           → future runs that reference it fail clearly; no credential switch
Rollback:  Remove execution support only after in-flight handled; do NOT drop AiConnection table
           or erase ciphertext on app rollback — keys stay while rows need decryption
           Prefer additive migration + forward fix (spec §10 Rollback)

Operations guide (reports/ai-connection-operations.md) documents key rotation and provider verification rehearsal. No production migration, paid test call, or Gmail live probe is run automatically — they are explicit owner gates (checklist §13 external acceptance).

Your tangible win — pre-flight checklist
Before enabling an AI Zap for anyone else, run this 5-point check:
  1. Input template leaf exists for the trigger (Gmail: {subject}/{snippet}/{body}; webhook: {raw} etc.)
  2. Mode + fields match downstream needs — no whole-object reference
  3. Provider shows “configured”; preview passes once (remember: billed)
  4. Daily cap > expected runs + previews × 2 (one spare for a repair)
  5. No money-moving action consumes raw AI output — validation gate in between
