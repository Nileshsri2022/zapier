Annotated sequence — what runAiStep does

export async function runAiStep(raw, resolvedInput, context, providerCall=callProvider)
{
  1) config = validateAiConfig(raw)                          // zod-ish checks: types, regex names, category/field bounds, connectionId/model rules
  2) policy = readAiPolicy(env)                              // integerEnv caps; malformed configured policy → AiStepError (startup fails fast)
     assert state?.repairUsed == false                       // second repair attempt would throw immediately
     input = resolvedInput.slice(0, policy.maxInputChars)    // truncation flag = (resolvedInput.length > input.length)
     assert input non-empty trimmed && config.maxOutputTokens ≤ policy.maxOutputTokens
     assert puter gate if needed
  3) connection = (provider==openai_compatible) ? await resolveConnection(id,userId) : undef
     apiKey = connection?.apiKey || env[OPENAI|ANTHROPIC|PUTER_*]   // missing → AiStepError before network
     assert /^[\x21-\x7E]+$/ && length ≤8192                 // coarse credential shape
     model = connection ? config.model! : platformModel(config, env)   // allowlist check for platform providers
     schema = buildJsonSchema(config)                        // classify→{category:enum}, extract→strict schema, else undefined
     request = { provider, model, apiKey, connection, schema,
                 system: systemPrompt(config,schema), input: frameInput(input),
                 temperature, maxOutputTokens, timeoutMs, maxResponseBytes, allowedHosts }
  4) invoke = async () => { await reserveCall(); result = await providerCall(request)
                           state.usage += result.usage  } // budget reservation = atomic Lua per attempt
     result = await invoke()                           // first provider call
  5) if (schema) validateAndCoerce( structured ?? parseJsonText(text) )
       catch → state.repairUsed=true
               request.system += "\nYour previous reply did not match… Return only corrected JSON…"
               result = await invoke();  fields = validate(result)   // exactly one repair attempt
               catch → throw "AI output repair failed: …"
     else    // plain-text modes: require non-empty text; summarize alias fields={summary:text}
     return { output, fields, provider, model, mode, usage:state.usage, truncated, latencyMs }
} catch (e) { throw safeAiError(e) }                  // normalizes AiConnectionError + unknown to AiStepError

What withRetry actually does — and does not

Two layers wrap AI: the inner repair (index.ts) and the outer withRetry in executeAiAction.ts:39:

return withRetry(
  async () => { /* replay guard → runAiStep → return {success:true, output} */ },
  { maxRetries:3, initialDelayMs:1000, shouldRetry: (e) => e instanceof AiStepError && e.retryable }
)
  • Retryable (from errors.ts:providerHttpError): 429 rate-limit and ≥500 provider errors, plus transport timeouts — via AiStepError(retryable:true). These get up to 3 retries with exponential backoff.
  • Fatal (not retried): 400/401/403/404, validation/repair exhaustion, empty input, invalid config, missing key/allowlist, budget reached, budget service unavailable when fail-closed.
  • Repair does not reset on retry. state.repairUsed is shared across withRetry attempts (executeAiAction.ts:32 createExecutionState() passed via context). A retry never gets a fresh repair.
  • Non-AI actions in the worker use withRetry without shouldRetry — they retry every throw (legacy behavior preserved). Only AI branch opts into predicate-based retry.

Repair — one extra try, not a loop

From packages/ai/src/index.ts:64:

let fields = {}
if (schema) {
  validate = (r) => validateAndCoerce( r.structured ?? parseJsonText(r.text ?? ""), config )
  try { fields = validate(result) }
  catch {
    state.repairUsed = true
    request.system += "Your previous reply did not match the required format…"
    try { result = await invoke(); fields = validate(result) }
    catch (e) { throw new AiStepError(`AI output repair failed: ${safeAiError(e).message}`) }
  }
} else {
  if (!result.text?.trim()) throw AiStepError("AI provider returned empty text")
  if (mode=="summarize") fields={summary: result.text}
}
  • The repair re-invokes the provider — billable, budget-counted — with an appended system line guiding JSON correction.
  • Second validation failure → run fails with a sanitized message (no raw provider body, raw URL, or credential leakage — safeAiError redacts).
  • Repair is guarded globally: if context.state?.repairUsed was already true (retry resuming after repair), it throws “already exhausted” before any network call.

Replay — the zero-cost path

apps/worker/src/executeAiAction.ts:46:

if (previousOutputs && Object.hasOwn(previousOutputs, context.stage)) {
  return { success:true, message:"AI step replay: reused stored output", output: previousOutputs[context.stage] }
}

Kafka is at-least-once (autoCommit:false in worker, offset committed after processMessage). A crash between successful provider response and DB persist, or a consumer rebalance after persist but before commit, can redeliver the same {zapRunId, stage}. On redelivery, the guard finds stepOutputs[stage] already stored — skips credential lookup and provider entirely.

Not exactly-once billing — if the provider accepted but the store never committed, the next delivery re-bills. Spec §4.5 and §6 say explicitly: “This is not exactly-once billing.”
