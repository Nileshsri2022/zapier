Pick by what the *next* step needs — paragraph, label, named values, or bespoke.

The chooser — start with downstream

The question to ask
What does the step after AI consume?
  • A short paragraph a human or email will read → summarize
  • One label to branch on (sentiment, topic, priority) → classify
  • Named typed values for an API/Sheet/DB → extract
  • Something not covered above — translation, reformat, rules → custom
This is also the flowchart in Mode chooser.

Four cards — what the model is told vs. what you get back

summarize · faithful short restatement

prompts.ts: modes.summarize — “Write a faithful summary. Preserve names, dates, amounts, links and decisions exactly.”

No JSON Schema sent. Plain text back. Envelope: output = text, fields = { summary: text }. Use when the next step interpolates {previousOutput.output} into a message.

classify · pick exactly one category

modes.classify — “Choose exactly one category from the provided list, the single best fit.”

Fixed schema { category: enum(categories) } via buildJsonSchema. 2–20 unique labels, each ≤60 ch. Envelope: output = String(category). Powers stepConditions on previousOutput.fields.category.

extract · pull structured facts

modes.extract — “Extract only values present. Missing optional → null. Numbers must be bare numbers.”

Your outputFields[1–25] become a strict JSON Schema (required = all names, optional = anyOf:[type,null], additionalProperties:false). Local validateAndCoerce checks every leaf. Envelope: output = JSON.stringify(fields).

custom · owner instructions define the task

modes.custom — “Perform the task specified by the workflow owner.” + your instructions (required, ≤4000 ch).

Two sub-modes: without outputFields → plain text (same as summarize); with fields → validated structured (same as extract). Common mistake: adding fields “just in case” without needing a named leaf.

Live shapes

What buildJsonSchema actually sends to the provider (see packages/ai/src/schema.ts):

// classify  → { type:"object", properties:{ category:{ type:"string", enum:["positive","neutral","negative"] } }, required:["category"], additionalProperties:false }

// extract → 1–25 fields → e.g. for the Priya order example (spec §5.3):
{
  type: "object",
  properties: {
    customerName: { type:"string" },
    email:        { type:"string" },
    orderId:      { type:"string" },
    amount:       { anyOf:[{type:"number"}, {type:"null"}], description:"Order amount as bare number" },
    issueType:    { type:"string", enum:["delivery","payment","quality","other"] }
  },
  required: ["customerName","email","orderId","amount","issueType"], // strict: every key must appear
  additionalProperties: false
}
Strict required + nullable trick
Strict JSON Schema providers require every key. ZapMate maps “optional business field” to “required but nullable” (anyOf:[property,{type:"null"}]). Validator then turns absent → null only when isRequired:false. Missing required → fatal, even after repair.

Field types & coercion — what actually passes validation

TypePasses asCoerced fromFail example
textstring—missing required → fail
numberfinite numbernumeric string "42" matching /^-?(\d+\.?\d*|\.\d+)(e[+-]?\d+)?$/i (schema.ts:57)"₹1,499" → fail (commas/currency)
booleanbooleanstrings "true"/"false""yes" → fail
category_singleone of options—"express" not in enum → fail
category_multiarray of options, deduped via Set—unknown entry or non-array → fail

Names: ^[a-zA-Z_][a-zA-Z0-9_]*$, ≤50 ch, reserves __proto__/prototype/constructor, unique. Category options: 2–50 unique, ≤60 ch. All checked in validateAiConfig + validateAndCoerce.

Recipe pair — same trigger, different mode

// Trigger: Webhook { raw: "Hi, I'm Priya (priya@example.com). My order 84120 of ₹1,499 never arrived." }

// classify (route by sentiment)
{ provider:"openai", mode:"classify", input:"{raw}", categories:["positive","neutral","negative"],
  instructions:"Classify the customer's sentiment. Sarcastic praise counts as negative." }
// → fields { category:"negative" } → stepCondition on next WhatsApp: previousOutput.fields.category == "negative"

// extract (pull fields for CRM)
{ provider:"openai", mode:"extract", input:"{raw}", outputFields:[
  { name:"customerName", type:"text", isRequired:true },
  { name:"email", type:"text", isRequired:true },
  { name:"orderId", type:"text", isRequired:true },
  { name:"amount", type:"number", description:"Bare number, no currency/commas", isRequired:false },
  { name:"issueType", type:"category_single", options:["delivery","payment","quality","other"], isRequired:true }
] }
// → fields { customerName:"Priya", email:"priya@example.com", orderId:"84120", amount:1499, issueType:"delivery" }

Notice: amount uses description to nudge “bare number”. That hint becomes property.description in the JSON Schema sent to the model.
