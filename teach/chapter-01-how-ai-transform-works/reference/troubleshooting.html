Troubleshooting AI Transform Failures

Map the error you see to the cause, the file that throws it, and the fix.

ReferenceErrors from AiStepError (packages/ai/src/errors.ts) and validateAiConfig
Three errors cause 80% of failures
  1. Empty input after templating — your {placeholders} matched nothing.
  2. Schema validation / repair exhausted — model returned shape that local validateAndCoerce rejected twice.
  3. Budget / auth / connectivity — daily cap, missing key, or allowed-host rejection before the call.

You see (status)CauseFix
AI step input resolved to empty text (400) replaceKeys(input, runMetadata) produced empty/whitespace; strict check in packages/ai/src/index.ts:36. Common when input:"{text}" but trigger payload uses {raw} or {subject}\n\n{snippet}. Match input to the trigger's real leaf keys (see Pipeline payload contract). Add a fallback literal or a preceding step that guarantees the key.
Invalid AI action configuration (411) validateAiConfig failed: bad regex names, duplicate field/category names, missing categories/outputFields for the mode, connectionId on non-compatible provider, empty model for compatible, temperature/tokens out of range. Re-open the editor; it shows AiActionMetaDataSchema issues. Check “Reserved field name” for __proto__/prototype/constructor and category duplicates.
AI output did not match the required format → AI output repair failed: … validateAndCoerce rejected the model's JSON; the one repair call (appended notice to system prompt, re-invoke) also failed. Root causes: numeric string with commas, boolean as “yes”, missing required field, extra unexpected enum value. Tighten instructions + field description (“Return amount as bare number, no commas/currency”). Add a coercion-friendly example. Lower temperature to 0 for extract.
AI provider returned empty text (400) Non-structured mode (summarize/plain custom) got whitespace-only text. Happens with empty-ish input that survived the earlier check but yields nothing. Ensure input has substantive content; raise maxOutputTokens if truncation left nothing to summarize.
AI output token setting exceeds … (411/400) Per-step maxOutputTokens > AI_MAX_OUTPUT_TOKENS policy cap. Checked on save and at execution. Lower per-step tokens or ask operator to raise policy cap.
Puter is disabled pending … (400) AI_PUTER_ENABLED != "true". Adapter exists but gate closed (spec Q6). Not user-fixable. Pick openai/anthropic or BYOK.
AI connection is unavailable / incompatible (400) Compatible provider: missing resolveConnection result, revoked connection, or AI_COMPATIBLE_ALLOWED_HOSTS empty / hostname not in allowlist (services/ai.ts:46). Re-create or re-authorize connection; verify operator allowlisted the hostname; check baseUrl is canonical HTTPS with no IP literal/query/fragment.
AI action configured but OPENAI_API_KEY … is not set Platform key missing for direct provider. platformModel also checks allowlist membership (config.ts:platformModel). Ask operator to set key + model defaults/allowlist. Switch to BYOK if you own a key.
AI model must be configured in … allowlist Requested model not in AI_MODEL_ALLOWLIST_{PROVIDER} or empty config. Pick a listed model in editor. Operator must extend allowlist for new models.
Daily AI call budget reached (429-ish) Redis Lua returned 0 — per-user or global cap hit for UTC day (budget.ts). Wait for UTC midnight; reduce retries/repairs/tests; request cap raise; check for loops. Remember test-panel probes count.
AI budget service unavailable; no provider call was made (503) Redis eval timed out/errored with AI_BUDGET_FAIL_OPEN=false (fail-closed default). No provider call made — other Zap actions still run. Check Redis health. Operator may set AI_BUDGET_FAIL_OPEN=true to let AI through best-effort (logs warning).
AI provider credential is invalid Key contains non-printable ASCII or >8192 ch (index.ts:51 coarse check). Re-paste key without trailing newline/space. BYOK keys go via connection API, not metadata.
AI provider request failed (HTTP 429 / 5xx) — retryable Provider throttled or errored. Classified retryable in providerHttpError. Worker retries up to 3× via withRetry({ shouldRetry: AiStepError.retryable }). Persistent 429 needs token-rate raise or backoff; 5xx is transient.
HTTP 4xx (400/401/403/404) — not retryable Auth or config rejected. Fatal — one attempt, then run fails. Fix key/model/connection; re-test via connection probe (billable) before re-enabling Zap.
AI provider response exceeded its size limit Streamed bytes > AI_MAX_RESPONSE_BYTES during reader.read(). Reduce maxOutputTokens or operator raises byte cap. Avoid models that dump huge traces.
AI provider refused, truncated or returned … finish_reason was length / content_filter / tool_calls (OpenAI) or max_tokens/refusal (Anthropic) — inspected in providers.ts:parseChatResponse + Anthropic branch. Raise token limit or shorten input; adjust instructions to avoid filter.
AI outbound concurrency limit reached >10 direct in-flight fetches in same Node process. Spread load across Zaps; concurrency is process-local — not a global cap.
AI execution requires owner-scoped budget accounting Worker bug context — invalid userId or missing reserveCall. Should not occur in normal Zaps. File an issue with ZapRun ID.
AI output repair attempt already exhaustedWorker retried the same stage execution after already using its repair. ExecutionState.repairUsed prevents infinite repair loops.Fix the root validation failure rather than retrying raw.

If you think you hit a bug

  1. Capture ZapRun ID + stage where the envelope should exist (ZapRun.metadata.stepOutputs[stage]).
  2. Note which error from the table above and whether it was after a repair (second provider call in logs).
  3. Check reports/ai-implementation-completion.md — was this marked “not production-accepted”?
  4. Open an issue with payload shape (redacted), raw config (minus secrets), and the error message.
