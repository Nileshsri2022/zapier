Which Mode Do I Need?

Four prompts, four shapes of answer — choose by what the *next* step needs.

ReferenceMaps packages/ai/src/prompts.ts + schema.ts to user intent
Start here — one question
What does the step after AI consume? A paragraph → summarize. A single label → classify. Named typed values → extract. “Something bespoke, maybe structured, maybe not” → custom. If you answer that, you have already chosen.
ModeWhen to useSystem hint (from prompts.ts)Schema / validationEnvelope
summarize Long → short, preserving names/dates/amounts/links/decisions. Human will read the result or it feeds an email/Slack message. Write a faithful summary. Preserve … exactly. No JSON Schema. Provider returns plain text; empty text → fatal. output = text
fields = { summary: text }
classify Route by sentiment/topic/intent. Needs 2–20 mutually exclusive labels. Powers a branch via stepConditions. Choose exactly one category from the provided list, the single best fit. Fixed schema { category: enum(categories) }. Required; unique categories ≤60 ch. output = String(category)
fields = { category }
extract Pull structured facts for a downstream API/DB/Sheet: names, emails, order IDs, amounts, dates, enums. Extract only values present … Missing optional → null. Numbers must be bare numbers. 1–25 OutputFields → strict JSON Schema via buildJsonSchema: required = all names, optional = nullable, additionalProperties:false. output = JSON.stringify(fields)
fields = { orderId, amount, … }
custom Anything not covered — translation, reformatting, rules (“Sarcastic praise = negative”). Structured optionally. Perform the task specified by the workflow owner. + your instructions. With outputFields → same strict schema as extract. Without → plain text like summarize. Structured: as extract; Plain: as summarize (alias fields = { summary } in impl.)

Flowchart — 30-second chooser

Is the goal to pick ONE label to branch on?
  ├─ yes → classify  (e.g. positive/neutral/negative; delivery/payment/other)
  └─ no → Do downstream steps need named values (orderId, email, amount)?
           ├─ yes → extract  (or custom+fields if you also need special rules)
           └─ no → Will a short paragraph be consumed as-is?
                    ├─ yes → summarize
                    └─ no → custom  (instructions define it; add fields only if you need structure)

Field types cheat sheet

Applies to extract and custom+fields only. Defined in packages/types/src/ai.ts and coerced in validateAndCoerce:

TypeWhat it accepts (after coercion)Example input→stored
textNon-empty strings"84120" stays string
numberFinite numbers; numeric strings like "42" / "1,499? no — bare only" coerced via regex. NaN/Infinity → fail."1499" → 1499
booleantrue/false; strings "true"/"false" coerced. Other strings → fail."true" → true
category_singleOne of 2–50 unique options (≤60 ch)issueType: "delivery"
category_multiArray of options, deduped via Set; extra keys dropped; unknown values → fail.["delivery","payment"]
Coercion is intentionally narrow: only string→number matching /^-?(\d+\.?\d*|\.\d+)(e[+-]?\d+)?$/i and "true"/"false"→boolean. Anything else must already be the right JSON type. See packages/ai/src/schema.ts:47.

Recipes — copy the closest one

Wh → AI summarize → Telegram

{
  "provider": "anthropic",
  "mode": "summarize",
  "instructions": "Summarize in at most 2 short sentences. Keep names, dates and amounts exact.",
  "input": "{text}"                 // WhatsApp payload root key
}
// Next step:  message = "📩 New WhatsApp from {fromName}:\n{previousOutput.output}"

Webhook → classify → conditional WhatsApp

{
  "provider": "openai",
  "mode": "classify",
  "instructions": "Classify the customer's sentiment about our service. Sarcastic praise counts as negative.",
  "input": "{message}",
  "categories": ["positive","neutral","negative"]
}
// stepConditions on next action: [{ field:"previousOutput.fields.category", operator:"equals", value:"negative" }]

Webhook → extract → downstream Webhook

{
  "provider": "openai",
  "mode": "extract",
  "input": "{raw}",
  "outputFields": [
    { "name": "customerName", "type": "text", "isRequired": true },
    { "name": "email",        "type": "text", "isRequired": true },
    { "name": "orderId",      "type": "text", "isRequired": true },
    { "name": "amount",       "type": "number", "description": "Order amount as bare number", "isRequired": false },
    { "name": "issueType",    "type": "category_single", "options": ["delivery","payment","quality","other"], "isRequired": true }
  ]
}
// Stored: { customerName:"Priya", email:"priya@example.com", orderId:"84120", amount:1499, issueType:"delivery" }
// Next Webhook body: { "name":"{previousOutput.fields.customerName}", "email":"{previousOutput.fields.email}" }
Custom with or without fields?
If your custom instructions can be answered as free text, leave outputFields off — the editor will store plain text. Add fields only when a downstream step or condition needs a named leaf (see Envelope for why a whole-object reference stringifies to [object Object]).
