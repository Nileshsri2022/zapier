The budget mechanism

RESERVE_AI_CALL_LUA  —  packages/ai/src/budget.ts:7

local userCap   = tonumber(ARGV[1])
local globalCap = tonumber(ARGV[2])
local userCount   = tonumber(redis.call('GET', KEYS[1]) or '0')
local globalCount = tonumber(redis.call('GET', KEYS[2]) or '0')
if (userCap > 0 and userCount >= userCap) or (globalCap > 0 and globalCount >= globalCap) then return 0 end
for i = 1, 2 do
  local count = redis.call('INCR', KEYS[i])
  if count == 1 then redis.call('EXPIRE', KEYS[i], 172800) end
end
return 1

Rules that surprise people

  • Repair consumes budget. The single validation-repair call reserves separately; a failed first attempt that got a billed response still counted.
  • Retries consume budget if they reach reserveCall() again inside withRetry. A timeout after the provider accepted the request can still bill.
  • Redis down ≠ “free” by default. With AI_BUDGET_FAIL_OPEN=false (default), the error is “AI budget service unavailable; no provider call was made” — the provider is never contacted. Non-AI steps still succeed. Fail-open must be explicitly opted into.
  • Character caps are not token/dollar caps. The spec calls this out: 20,000 characters ≠ 5,000 tokens across languages/tokenizers (§7). Set provider-side spend controls too.
  • Test-panel calls count. Both POST /api/actions/ai/test and POST /api/ai/connections/:id/test call createDailyBudget(...).reserveCall() with the same Lua.

Quick self-check

Before asking “why did my AI step fail?”, scan this checklist (details in Troubleshooting):

  1. Is input template empty after replaceKeys? → “input resolved to empty text”
  2. Does maxOutputTokens exceed policy cap? → exceeds configured limit
  3. Are you on puter without AI_PUTER_ENABLED=true? → disabled
  4. Is openai_compatible missing owned connection or approved host? → unavailable
  5. Daily cap hit or Redis down with fail-closed? → budget error
