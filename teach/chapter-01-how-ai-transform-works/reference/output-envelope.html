How validation shapes the envelope

Built in packages/ai/src/schema.ts:buildJsonSchema:

  • classify → { type:"object", properties:{ category:{ enum: categories } }, required:["category"], additionalProperties:false }
  • extract/custom+fields → one properties entry per field; required: outputFields.map(f=>f.name) but optional business fields are allowed as { anyOf:[property,{type:"null"}] } — strict schemas need every key present.
  • validateAndCoerce then checks required/nullable, finite numbers, boolean/string coercion, enum membership, array deduping, and drops extra keys.
Why two forms — output and fields?
Templates in replaceKeys do String(value). A whole object becomes [object Object]. So ZapMate persists both: output for anywhere a string is needed (a single interpolated email/hook body) and fields for dot-path access and conditions. See apps/worker/src/utils/replaceKeys.ts and Spec §4.4 caveat.

Referencing — what actually resolves

// After an extract step at stage 1 that produced { orderId:"84120", amount:1499 }
// In a later step's body or subject:
{previousOutput.output}                 // → '{"orderId":"84120","amount":1499}'  (raw string)
{previousOutput.fields.orderId}         // → "84120"
{previousOutput.fields.amount}          // → "1499"  (String(1499) after replaceKeys)
{stepOutputs.1.fields.orderId}           // → same, indexed by stage

// In a step condition:
field: "previousOutput.fields.category"  value: "negative"  operator: "equals"

// These do NOT do what you expect:
{previousOutput.fields}                 // → "[object Object]"  (avoid)
{previousOutput.fields.unknown}         // → "" (unknown placeholder stays → "" via replaceKeys fallback)

// Framing: content between input markers is untrusted data — see prompts.ts system prompt.

usage and truncated semantics

  • usage is provider-reported only (e.g. OpenAI prompt_tokens/completion_tokens, Anthropic input_tokens/output_tokens via reportedUsage in providers.ts). If the provider omits it, the envelope omits it. Repair counts are aggregated across initial + repair calls (summing state.usage in index.ts:42).
  • truncated: resolvedInput.length > input.length. Input is sliced to AI_MAX_INPUT_CHARS (default 20,000) before framing. The model never sees the tail.
  • latencyMs covers the whole attempt including any repair and reserveCall().

Failure envelope

Failures do not produce the table above. The worker records ZapRun.status:"failed" + errorMessage: AiStepError.message and optionally emails the owner via sendZapFailureNotification. See Troubleshooting for the error catalog.
